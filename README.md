# Сбор файлов ОО

Nextcloud ExApp для организации мониторингов и сбора файлов от образовательных организаций. Приложение работает от имени текущего пользователя Nextcloud через WebDAV и OCS Share API: создаёт папки, публичные ссылки, проверяет загруженные файлы, формирует отчёты и помогает отправлять напоминания.

## Возможности

- Справочник организаций: школы, сады, ОДО, УДОДы и другие типы.
- Ручное добавление, редактирование и удаление организаций.
- Импорт и экспорт справочника в XLSX/CSV.
- Хранение email, дополнительных email, алиасов и активности организации.
- Создание мониторингов с названием, сроком сдачи, корневым путём, типами ОУ и разрешёнными расширениями.
- Выбор расширений через компактный multi-select.
- Создание структуры папок мониторинга в Nextcloud.
- Три режима публичных ссылок:
  - одна upload-only ссылка "Запрос файла" на корень мониторинга;
  - upload-only ссылка "Запрос файла" на каждый тип ОУ;
  - отдельная ссылка редактирования для каждой организации.
- Для режима отдельных ссылок организаций доступна структура папок:
  - авто;
  - организации в корне мониторинга;
  - организации внутри папок типов ОУ.
- Удаление всех публичных ссылок мониторинга.
- Проверка загруженных файлов: нормализация имён, поиск дублей, мусорных файлов и организаций без файла.
- Сохранение результата проверки как отдельного запуска.
- Формирование XLSX-отчёта, XLSX/TXT списка ссылок и текстового списка не предоставивших файлы.
- Рассылка напоминаний организациям, которые не предоставили файл.
- Массовое переименование файлов по шаблону.
- Перемещение мониторинга и отправка в архив.
- История запусков операций по каждому мониторингу.
- Общий лог: что, когда и кем запускалось.
- Настройки корневой папки, архива и группы доступа.
- Проверка WebDAV-доступа и тестовая отправка письма на email текущего пользователя.

## Рабочий процесс

1. Заполните справочник ОУ вручную или импортом XLSX/CSV.
2. В настройках выберите корневую папку мониторингов, папку архива и группу доступа.
3. Создайте мониторинг: выберите типы ОУ, расширения файлов и режим ссылок.
4. В разделе "Операции" создайте папки.
5. Создайте публичные ссылки.
6. Скачайте таблицу ссылок или сформируйте письма.
7. После загрузок выполните проверку файлов.
8. Сохраните результат проверки, просмотрите отсутствующие ОУ и ошибки.
9. При необходимости отправьте напоминания, переименуйте файлы или выгрузите отчёт.

## Режимы папок и ссылок

### Одна ссылка на корень

Создаётся одна публичная ссылка на корневую папку мониторинга. Ссылка создаётся как file request: в интерфейсе Nextcloud это режим "Запрос файла".

Практический смысл: самый простой вариант, когда все организации загружают в одну точку. Организации не получают права редактировать уже загруженные файлы.

### Ссылка на каждый тип ОУ

Внутри мониторинга создаются папки типов, например `Школы`, `Сады`, `ОДО`, `УДОДы`. На каждую такую папку создаётся отдельная file request ссылка "Запрос файла".

Практический смысл: загрузки разделены по типам ОУ, но внутри типа организации всё ещё загружают через общую upload-only ссылку.

### Ссылка для каждой организации

Для каждой организации создаётся своя папка и отдельная публичная ссылка с правом редактирования.

Практический смысл: организация видит и редактирует только свою папку. Этот режим нужен, если важно иметь индивидуальные ссылки и готовую структуру по организациям.

### Структура папок организаций

Параметр "Структура папок" используется только для режима "Ссылка для каждой организации".

- `Авто`: если выбран один тип ОУ, папки организаций создаются в корне мониторинга; если типов несколько, создаются папки типов.
- `Организации в корне`: все организации лежат прямо внутри папки мониторинга.
- `Организации внутри типов`: организации раскладываются внутри папок `Школы`, `Сады` и т.д.

Для режимов "Одна ссылка на корень" и "Ссылка на каждый тип ОУ" структура организаций не применяется, потому что отдельные папки организаций там не создаются.

## Операции и история

В разделе "Операции" есть вкладки:

- `Лог`: общая история действий по мониторингу.
- `Папки`: создание папок мониторинга.
- `Ссылки`: создание и удаление публичных ссылок.
- `Проверка`: проверка загруженных файлов.
- `Рассылка`: подготовка и отправка напоминаний.
- `Переименование`: массовое переименование файлов.

Каждый запуск создаёт отдельный `run_id`. Новый запуск не затирает старый: история хранится по типу операции и доступна в карточках результатов. Для каждого запуска сохраняются сводка, статус, время запуска, инициатор и подробный вывод по элементам.

## Проверка файлов

Проверка анализирует файлы внутри папки мониторинга и сопоставляет их с организациями из справочника.

Проверка умеет:

- учитывать выбранные расширения мониторинга;
- сопоставлять организацию по номеру и алиасам;
- нормализовать имена файлов;
- находить дубли;
- выделять неподходящие и неизвестные файлы;
- формировать список организаций, которые не предоставили файл.

После preview результат можно сохранить. Сохранённая проверка используется для отчётов и рассылки напоминаний.

## Рассылка

Рассылка работает по результату последней сохранённой проверки файлов.

Приложение берёт организации из списка "не предоставили", формирует письмо по шаблону и использует ссылку, сохранённую для этой организации или её группы. Если у организации нет email, письмо помечается ошибкой и не отправляется.

Важно:

- Рассылка не отправляет письма всем организациям мониторинга, а только тем, кто отсутствует в сохранённой проверке.
- Если ссылки ещё не созданы, в письме не будет корректной ссылки для загрузки.
- Для режимов "Одна ссылка на корень" и "Ссылка на каждый тип ОУ" несколько организаций могут получить одну и ту же upload-only ссылку.
- Для режима "Ссылка для каждой организации" каждая организация получает свою ссылку редактирования.
- Дополнительные email хранятся в справочнике, но текущий почтовый bridge отправляет письмо на основной email организации.

## Особенности работы почты

ExApp-контейнер не отправляет почту напрямую через SMTP. Он вызывает небольшой PHP bridge внутри Nextcloud, а bridge уже отправляет письмо через стандартный почтовый сервис Nextcloud (`OCP\Mail\IMailer`).

Так сделано потому, что почтовые настройки уже находятся в Nextcloud, а ExApp работает в отдельном контейнере. На практике это означает:

- SMTP должен быть настроен в самом Nextcloud.
- Nextcloud должен успешно отправлять тестовые письма из административных настроек.
- У организаций в справочнике должен быть заполнен email.
- У текущего пользователя Nextcloud должен быть заполнен email, иначе проверка почты из настроек приложения не сможет отправить тестовое письмо.
- Для связи ExApp с bridge нужен общий секретный token.

### Что нужно сделать на новом сервере для почты

1. Настройте почтовый сервер в Nextcloud: `Администрирование -> Основные настройки -> Почтовый сервер`.
2. Проверьте отправку стандартным тестом Nextcloud.
3. Скопируйте `oo_file_collector_mail_bridge.php` в корень установки Nextcloud, например:

```bash
cp oo_file_collector_mail_bridge.php /var/www/html/oo_file_collector_mail_bridge.php
```

4. Создайте общий token:

```bash
openssl rand -hex 32 > /tmp/oo_file_collector_mail_bridge_token
```

5. Положите этот token в Nextcloud рядом с приложением:

```bash
mkdir -p /var/www/html/custom_apps/oo_file_collector
install -m 640 -o www-data -g www-data /tmp/oo_file_collector_mail_bridge_token \
  /var/www/html/custom_apps/oo_file_collector/mail_bridge_token
```

6. Положите тот же token в persistent storage ExApp. При стандартном Docker-развёртывании это `/data/mail_bridge_token` внутри контейнера:

```bash
docker cp /tmp/oo_file_collector_mail_bridge_token nc_app_oo_file_collector:/data/mail_bridge_token
docker exec nc_app_oo_file_collector chmod 600 /data/mail_bridge_token
```

7. Проверьте в приложении: `Настройки -> Проверить почту`.

Если Nextcloud установлен не в `/var/www/html` или каталог приложения отличается от `custom_apps/oo_file_collector`, поправьте пути под свою установку. Standalone bridge сейчас ожидает token по пути `custom_apps/oo_file_collector/mail_bridge_token` относительно корня Nextcloud.

## Настройки приложения

В интерфейсе доступны:

- `Корневая папка`: папка, внутри которой разрешены все операции приложения.
- `Каталог архива`: куда перемещаются архивные мониторинги.
- `Группа доступа`: одна группа Nextcloud, которой приложение выдаёт доступ к корневой папке, если это не Team Folder.
- `Проверить`: проверка доступа к корню через WebDAV.
- `Проверить почту`: отправка одного тестового письма на email текущего пользователя.

Группы подгружаются по кнопке "Обновить", чтобы не делать лишние запросы при каждом открытии приложения.

## Team Folders и права доступа

Рекомендуемый вариант для совместной работы: создать корневую папку мониторингов как Team Folder и указать её в настройках приложения, например `/Monitoringi` или `/Мониторинги`.

Если корневая папка является Team Folder, права управляются Nextcloud Team Folders, а приложение работает внутри неё через WebDAV.

Если корневая папка принадлежит пользователю, приложение может создать group share для указанной группы доступа. В этом fallback-режиме группа получает доступ к содержимому папки, но владелец папки остаётся текущим пользователем. Это нормальный вариант, но для стабильной совместной работы Team Folder обычно понятнее и предсказуемее.

Путь `/` нельзя расшарить группе как fallback. Нужно указывать конкретную папку.

## Безопасность и ограничения

- Приложение не работает с файловой системой Nextcloud напрямую.
- Все операции с файлами выполняются через WebDAV.
- Все публичные ссылки создаются через OCS Share API.
- Операции ограничены корневой папкой из настроек.
- Пути нормализуются, `..` и выход за корневую папку запрещены.
- Массовые операции имеют preview/apply модель: сначала план, потом применение.
- Табличные экспорты экранируют значения, похожие на формулы.
- Пользовательские роли внутри приложения не реализованы; права зависят от текущего пользователя Nextcloud и прав на папки.
- Изменения, сделанные пользователями напрямую в UI Nextcloud, приложение не может полностью запретить. Проверка файлов пересканирует фактическое состояние папки.

## Развёртывание как ExApp

Ожидаемая инфраструктура:

- Nextcloud 30-35.
- Установлен и включён AppAPI.
- Настроен Deploy Daemon/HaRP для Docker.
- ExApp-контейнер запускается в сети, доступной AppAPI/HaRP.
- Внешний проброс порта приложения обычно не нужен: трафик идёт через AppAPI/HaRP.

Перед публикацией проверьте `appinfo/info.xml`:

```xml
<registry>ghcr.io</registry>
<image>kyasu-404/oo_file_collector</image>
<image-tag>1.0.5</image-tag>
```

Если используете свой registry или tag, замените значения и опубликуйте Docker image.

Минимальные шаги:

```bash
docker build -t ghcr.io/kyasu-404/oo_file_collector:1.0.5 .
docker push ghcr.io/kyasu-404/oo_file_collector:1.0.5
```

После установки приложения в Nextcloud:

1. Откройте приложение "Сбор файлов ОО".
2. В настройках укажите корневую папку мониторингов.
3. Нажмите "Проверить".
4. Настройте почтовый bridge, если нужна рассылка.
5. Нажмите "Проверить почту".

Для чистого развёртывания лучше явно задать `MRM_ROOT_PATH=/Мониторинги` через настройки ExApp/AppAPI или сразу сохранить этот путь в настройках приложения.

## Переменные окружения

- `APP_PERSISTENT_STORAGE`: persistent storage, который AppAPI может передать ExApp.
- `MRM_STORAGE_DIR`: storage directory приложения, если `APP_PERSISTENT_STORAGE` не задан.
- `MRM_DATABASE_URL`: SQLAlchemy URL. По умолчанию SQLite в persistent storage.
- `MRM_ROOT_PATH`: корневая папка мониторингов.
- `MRM_DUPLICATES_FOLDER`: имя папки дублей.
- `MRM_INVALID_FOLDER`: имя папки неподходящих файлов.
- `MRM_ARCHIVE_FOLDER`: каталог архива.
- `MRM_DEFAULT_EXTENSIONS`: расширения по умолчанию через запятую.
- `MRM_WEBDAV_PARALLELISM`: параллелизм WebDAV-операций.
- `MRM_REQUEST_TIMEOUT`: timeout запросов к Nextcloud.
- `MRM_NC_BASE_URL` или `NEXTCLOUD_URL`: базовый URL Nextcloud, если не приходит через AppAPI.
- `MRM_NC_USER`: пользователь Nextcloud для fallback-режима без AppAPI.
- `MRM_NC_APP_PASSWORD`: app password для fallback-режима без AppAPI.
- `MRM_LOG_LEVEL`: уровень логирования Uvicorn.

Переменные `HP_SHARED_KEY`, `HP_FRP_ADDRESS`, `HP_FRP_PORT`, `APP_PORT`, `APP_ID` обычно передаются AppAPI/HaRP автоматически.

## Локальная проверка

```powershell
python -m pip install -r requirements-dev.txt
python -m pytest
node --check ex_app/js/monitoringi-main.js
```

Полноценная проверка WebDAV, OCS Share API, Team Folders и почты требует живой Nextcloud с AppAPI.

## Структура проекта

- `appinfo/`: метаданные Nextcloud-приложения и маршруты.
- `ex_app/lib/`: FastAPI backend.
- `ex_app/js/monitoringi-main.js`: основной интерфейс.
- `ex_app/css/monitoringi.css`: стили интерфейса.
- `oo_file_collector_mail_bridge.php`: standalone PHP bridge для отправки почты через Nextcloud.
- `Dockerfile`, `start.sh`, `healthcheck.sh`: контейнер ExApp.
- `tests/`: unit-тесты ключевой логики.
